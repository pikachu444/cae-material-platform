# 스키마 정의 세트(Schema Bundle v1)

> 원본: `물성DB통합개발기획.pdf` 7쪽

사내 물성 DB 구조를 JSON 한 세트로 정의한 것이다. 두 가지 용도로 쓴다.

1. **오픈소스 요구사항 P1(스키마 번들 import)의 입력 픽스처:** 이 세트를 그대로 import 테스트 데이터로 사용한다.
2. **내부 PoC 시딩 스크립트의 입력:** P1 반영 전에도 내부에서 기존 API를 순차 호출하는 스크립트로 동일 구조를 세팅할 수 있다(`scripts/seed_full_demo.py` 패턴 참조).

## 구성

```text
catalog-schema-bundle.manifest.json  <- 번들 매니페스트: DB/Profile/Table 목록/LinkType/단위 프로파일/import 정책
record-schemas/
  technical-data-v2.json             <- 베이스 추상 소재 데이터(중심 허브)
  tensile-test-v2.json                <- 인장 시험(원천 데이터)
  dma-test-v1.json                    <- DMA 점탄성 시험(원천 데이터, 신규)
  fld-test-v1.json                    <- FLD(독립 데이터타입 예시, 신규)
  elastoplasticity-v2.json            <- 탄소성 프로세싱 데이터(시험별 중립 데이터)
  statistics-v2.json                  <- 다수 시편 통계 대표 데이터
```

솔버 카드는 솔버별 고유 형식이 있으므로 의도적으로 제외한다. 플랫폼의 Export/IR 경로를 사용한다.

## 링크 구조(GRANTA 구조 승계)

```text
Technical Data (1) -> Tensile Test (N) -> Elastoplasticity (N) -> [IR/Neutral] -> Solver Card
                 (1) -> DMA Test (N)
                 (1) -> FLD Test (N)

Tensile Test (N) <-> Statistics (M)  - 다수 시편 -> 대표값
```

플랫폼에서는 exact-revision `RecordLink` + `LinkType`으로 표현되며 `Workflow Explorer`(양방향 BFS)로 계보 추적이 된다(`backend/src/cmp/modules/catalog/domain/links.py`).

## v1 대비 변경점

| 변경 | 이유 |
| --- | --- |
| 모든 속성에 `x-key` 추가 | 플랫폼 Attribute key 규칙이 `^[a-z][a-z0-9_]{0,63}$`이므로 표시명(`"Spec Thickness (mm)"`)과 기계 키를 분리해야 한다. |
| `x-quantity` 추가 | 플랫폼의 `quantity_semantics` 필드에 대응(예: `mechanics.stress.true`) |
| `x-discrete` / `x-discrete-open` 추가 | 플랫폼 discrete attribute의 `allowed_values`에 대응. `-open`은 제안값만 있고 자유 입력을 허용한다. |
| `x-id-rule` 추가 | 사내 고유 ID 명명 규칙을 스키마에 문서화(자동 생성 규칙) |
| DMA/FLD 스키마 신설 | GRANTA 테이블 승계(Creep-Relaxation, Adhesive, Fatigue, Dielectric, Compression은 동일 패턴으로 추후 추가) |
| `statistics`에 분포 모델/envelope 명시 | 오픈소스 통계 기능 요구(P5)의 목표 형식 |

## `x-` 확장 -> 플랫폼 개념 매핑(P1 구현 규칙)

| `x-` 확장 | 플랫폼 대응 | 비고 |
| --- | --- | --- |
| `x-table-key` | Table key | 스키마 파일 -> Table 1:1 |
| 그룹 객체(예: `"Test Condition"`) | Layout 그룹 | 화면 배치로 활용 |
| `x-key` | Attribute key | 필수. 없으면 표시명에서 유도 불가로 오류 |
| `type:number + x-unit` | `data_type:number + normalized_unit + x-quantity -> quantity_semantics` | 원본값·원본단위 동시 보존은 플랫폼 기본 지원 |
| `type:string + x-discrete` | `data_type:discrete + allowed_values` |  |
| `type:string`(일반) | `data_type:text` | `format:date -> data_type:date` |
| `x-business-key:true` | Record `external_key`에 기록 + 중복 차단 | Attribute로도 이중 저장(검색용) |
| `x-indexed` / `x-searchable` | 검색 프로젝션 노출 플래그 | 현재 플랫폼은 속성별 지정 불가 -> P1 범위에서 협의 |
| `x-reference{schema_key,pointer}` | `data_type:record_reference` + LinkType 자동 생성 + business key -> UUID 해석 | 매니페스트 `link_types[].derived_from`과 일치해야 함 |
| `x-curve{...}` | `data_type:curve`(artifact) + 곡선 채널 메타데이터(x/y/series/deviation pointer, 단위, 스케일) | 채널 메타 저장은 현재 플랫폼에 없음 -> P2 요구사항 |
| `deviation_pointer` | 편차(표준편차) 채널 | 현재 플랫폼에 개념 없음 -> P2 |

## 단위 정책

- **원천/화면 표시:** `cae_mm_t_s` 프로파일(mm, tonne/mm³, MPa) - 기존 GRANTA 관례
- **내부 정규화:** 플랫폼 정규화 단위 사용(Pa 등) - 단위 변환 확장은 P3 요구사항
- **주의:** 기존 데이터에 `tonne/mm3`(Technical)와 `kg/m3`(EP)가 혼재하므로 import 시 명시 변환이 필요하다.
