# 내부 빌드·검증 계획

> 원본: `물성DB통합개발기획.pdf` 8쪽

외부 저장소에는 push/PR이 불가하므로 내부 저장소(사내 GitHub)에 미러를 두고 빌드·실데이터 검증을 수행한다. 외부에는 요구사항 패킷(02 문서)만 전달한다.

## 0. 저장소 운영

- **내부 미러:** 외부 `main`을 주기적으로 fetch -> 내부 `upstream` 브랜치에 반영. 내부 수정(PoC 스크립트, 사내 설정, 실데이터 픽스처)은 `internal/*` 브랜치에 둔다. upstream과 섞지 않는다(요구사항이 반영되면 내부 패치를 버리는 것이 원칙).
- **내부 전용 산출물:** `internal-tools/` 디렉터리(시딩 PoC, 데이터 변환기, 비교 스크립트), 사내 실데이터 픽스처(보안 등급 준수, 외부 반출 금지).
- 외부 이슈 등록 이력과 내부 검증 결과를 이 폴더(`기획_및_요구사항/`)에 기록한다.

## 1. 환경 구축(2트랙)

### 1a. 주 경로 - Hyper-V Ubuntu VM + Docker Engine(이슈 #162와 동일 방향)

라이선스: Docker Engine/Compose 플러그인은 Apache-2.0(Docker Desktop 아님 -> 구독 불필요), WSL 미사용.

1. Hyper-V 관리자에서 2세대 VM 생성: Ubuntu 22.04/24.04 LTS, vCPU 4+, RAM 8GB+(권장 16), 디스크 80GB+, 기본 스위치(NAT).
2. VM 내부: `apt install docker-ce docker-compose-plugin`(docker.com 공식 저장소), `git clone <내부 미러>`.
3. 실행:

```bash
docker compose -f deploy/compose/docker-compose.demo.yml config --quiet
docker compose -f deploy/compose/docker-compose.demo.yml up --build -d
docker compose -f deploy/compose/docker-compose.demo.yml ps --all
```

판정: `postgres`·`api` healthy, `migrate`·`reference-plugins`·`seed` 종료코드 0. seed가 멈추면 이슈 #157 재현 절차를 참조한다(README에 명시된 알려진 결함).

4. 호스트 접근: VM IP로 `http://<vm-ip>:5173`(web), `:8000/api/v1/health`(API). 방화벽/포트포워딩을 문서화한다.
5. 주의: compose가 postgres 54329/API 8000/web 5173을 `0.0.0.0`에 바인딩한다. VM 방화벽(UFW)에서 사내망 노출 범위를 제한한다.

### 1b. 보조 경로 - Windows 네이티브(Docker 전면 불가 시)

구성 5개: PostgreSQL 16(Windows 설치본, extension 불필요) / Python 3.12 + uv / Node 20 / NTFS 오브젝트 스토어 폴더 / 시크릿 2개.

```powershell
# 1) DB 준비 후 마이그레이션 + 부트스트랩
$env:CMP_DATABASE_URL="postgresql+psycopg://cmp_owner:<pw>@127.0.0.1:5432/cmp"
uv sync --all-groups
npm ci
uv run alembic -c alembic.ini upgrade head

$env:CMP_ENVIRONMENT="demo"
$env:CMP_DEMO_IDENTITY="true"
$env:CMP_DEMO_APP_DATABASE_PASSWORD="<pw2>"
uv run cmp-demo-bootstrap

# 2) 서비스(각각 별도 창) - cmp_app DSN + 스토리지/시크릿 설정 후
uv run cmp-api                         # :8000
uv run cmp-worker
npm run dev --workspace @cmp/web       # :5173 (API 프록시 내장)

# 3) 시드
uv run cmp-demo-seed --api-base-url http://127.0.0.1:8000/api/v1
uv run python scripts/seed_full_demo.py --api-base-url http://127.0.0.1:8000/api/v1
```

제약: 공식 문서화되지 않은 경로(자체 검증 필요), 오브젝트 스토어는 NTFS 하드링크 필요(네트워크 드라이브 불가), `CMP_ENVIRONMENT=production` 금지(코드가 S3+KMS를 강제).

### 공통 보안 수칙

- `CMP_DEMO_IDENTITY=true`는 접속자 전원이 관리자가 되는 데모 전용 스위치다. 검증망 밖 노출 금지. P8(로그인) 반영 전에는 사내 IdP 연동 시 UI가 동작하지 않을 것을 전제로 검증망에서만 사용한다.
- Swagger(`/docs`)는 production 환경값이 아니면 노출된다.

## 2. 검증 단계

### V0 - 데모 스모크(지금 즉시)

- [ ] compose(또는 네이티브) 기동, health 200, 데모 시드 완료
- [ ] DP780 검색 -> 상세 -> CAE Card 미리보기/다운로드
- [ ] Modeling: Data -> Process -> Fit(4개 경화모델 비교) -> Export 흐름 통과
- [ ] Activity: 리뷰 요청 -> 승인(데모는 동일 principal이라 SoD로 자기승인 불가. 계정 2개 상황은 P8 이후)
- [ ] Administration: Table/Attribute 초안 -> 발행, Record 단건/다건 등록

**산출:** 스모크 결과표. 재현 실패 항목은 외부 이슈로 보고(특히 #157 관련).

### V1 - 사내 구조 PoC(P1 반영 전, 내부 스크립트로 선행)

**핵심:** P1을 기다리지 않고 기존 API만으로 사내 구조를 세팅하는 PoC 스크립트를 내부 작성한다. `scripts/seed_full_demo.py`의 멱등 패턴을 복제해 `03_스키마정의/` 번들을 읽고 Table 6종 + LinkType 6종을 생성한다.

- [ ] 스키마 번들 -> 카탈로그 구조 생성 스크립트(`internal-tools/seed_smx_schema.py`)
- [ ] GRANTA 내보내기 샘플(비민감 10-20건) 레코드 등록 변환기: Technical/Tensile/DMA/EP/Statistics + 링크 + `external_key`
- [ ] Workflow Explorer로 `Technical -> Tensile -> EP` 계보 조회 확인
- [ ] 곡선 artifact 업로드·조회 확인(채널 메타 부재 상태의 한계 기록 -> P2 요구 근거)

**산출:** PoC에서 드러난 매핑 문제 목록 -> P1 스펙 피드백(외부 이슈 코멘트).

### V2 - 실데이터 E2E 대조(프로세싱 신뢰성)

- [ ] 실제 인장 raw(`.tra`/`.csv`) 3개 소재 × 5시편: governed import -> Process(smoothing/crop/true 변환) -> Fit
- [ ] 대조 기준: 인하우스 코드/GRANTA 결과와 비교 - 탄성계수 ±2%, 0.2% proof stress ±2%, 경화곡선 RMSE 합의 한도 내
- [ ] toe가 있는 데이터로 보정 부재의 영향 정량화(-> P10 근거 데이터)
- [ ] DMA 데이터: `shear_relaxation` 우회 경로로 Prony 피팅 시도, 제약 기록(-> P4 근거)
- [ ] Abaqus 카드 추출 -> 사내 표준 카드와 diff -> 단위계(kg-m-s 고정) 영향 기록(-> P3/P6 근거)

**산출:** 대조 리포트(수치 표), 허용오차 밖 항목의 원인 분석.

### V3 - 요구사항 반영분 회귀 테스트(패킷별)

각 패킷 반영 시 upstream 동기화 후 다음을 검증한다.

- **P1:** 번들 `:plan/:apply/재적용 0건/:export` 왕복 - `03_스키마정의` 픽스처 그대로
- **P2:** `statistics` 대표 곡선 편차 밴드 표시
- **P3:** `tonne/mm3 <-> kg/m3`, `degC` 정규화
- **P5:** 시편 그룹 -> `mean/p05/p95 + Weibull` - 인하우스 통계 결과와 대조
- **P6:** LS-DYNA `MAT_024` 템플릿 등록 -> 사내 표준 `.k` 카드와 diff
- **P7:** 업로드 승인 E2E(계정 2개), 역할별 403 매트릭스
- **P8:** 사내 IdP(또는 검증용 Keycloak) 로그인
- **P9:** 행위 -> audit 이벤트 존재, integrity 통과

### V4 - 운영 준비 판정

- [ ] 성능: 사내 예상 규모(레코드 수만 건) 시딩 후 검색 p95 < 500ms(저장소 기준치 준용)
- [ ] 백업/복구: `pg_dump/restore` 드릴 + 오브젝트 스토어 동시 복구
- [ ] 권한 매트릭스 전수 점검(3역할 × 주요 API)
- [ ] 미결 리스크 재평가: audit fail-closed 정책, 보존/삭제 정책(현재 물리 삭제 경로 없음), S3/KMS 필요 여부

## 3. Upstream 동기화 규칙

1. 외부 릴리스/병합 단위로 fetch, `upstream` 갱신 -> 내부 검증 브랜치 rebase.
2. V0 스모크 자동 재실행(최소 health + 검색 + 카드 다운로드) 후 통과 시에만 내부 기준선 승격.
3. 반영된 패킷은 V3 항목을 1회 수행하고 결과를 외부 이슈에 피드백한다(재요구 시 구체 로그 첨부).
