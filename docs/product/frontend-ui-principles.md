# 프론트엔드 UI 원칙

공학 데이터를 조회·비교·계산하는 서비스의 화면 기준이다. 데이터 의미는 [데이터 정책](data-management-policy.md), 구현 책임은 [아키텍처](../architecture/frontend-architecture.md), 검증 범위는 [시각 매트릭스](visual-acceptance-matrix.md)에서 관리한다.

## 현재 화면 기준 — 2026-09-07

사용자는 [소재 중심 대표 화면](../../design/frontend-reader-proposals/material-workspace/index.html)의 큰 구조를 구현 기준으로 삼는 데 동의했다.
소재의 카드/표, 왼쪽 소재·시편 트리와 별도 필터, 오른쪽 미리보기, 목록을 숨기는 확대 상세와 복귀를 기준으로 한다.
필터 항목·기본값·표의 열·표시 물성·문구·색상 세부값·패널 폭은 실제 데이터와 사용성 검증에 맞춰 조정 가능하다.
이 동의는 합성 자료의 공학적 승인, 실제 API 연결 완료, 물리 4K 가독성 승인 또는 제품 전환을 뜻하지 않는다.
결정 이력은 [ADR-0037의 후속 결정](../../adr/0037-task-first-frontend-foundation.md)에 남긴다. 이전 A/B와 여섯 비교안은 평가 이력이다.

## 업무와 탐색

- 실험 데이터 조회, 기존 솔버 카드 조회·다운로드가 우선이다. 소재를 선택하지 않고도 각각 직접 진입한다.
- 소재에서 관련 시편·실험·처리 결과·모델·카드를 찾을 수 있게 한다. 연결은 다중일 수 있으며 반드시 거쳐야 하는 화면 순서가 아니다.
- 왼쪽 업무 메뉴와 소재/시편 트리, 검색 조건 필터의 역할을 구분한다. 필터는 현재 데이터 종류에 맞춰 제공하고 지원되지 않는 조건으로 검색한 것처럼 표시하지 않는다.
- 선택은 오른쪽 미리보기, 더블클릭·Enter·상세보기는 확대 상세다. 미리보기를 접어도 선택과 다중 선택을 임의로 잃지 않는다.
- 목록으로 돌아오면 검색·필터·페이지·선택·스크롤·초점이 복원된다. 페이지 변경 후 이전 항목이 새 페이지의 선택인 것처럼 보이지 않게 한다.
- 넓이가 부족하면 사용자가 알 수 있는 전환과 목록 복귀를 제공한다. 목록 아래에 미리보기를 조용히 쌓지 않는다.
- 처리·모델 생성은 입력과 그래프 중심으로 구성한다. 모든 업무에 조회 화면의 패널 배치를 강제하지 않는다.
- 처리 결과 다운로드와 솔버 카드 추출을 별도 행동으로 제공한다. 저장된 결과를 사용하려고 다시 계산하거나 생성하게 하지 않는다.

## 공학 정보 표기

물성은 **항목·값·단위·조건**을 각각 읽을 수 있어야 한다. 제목에 조건을 몰아 넣거나 줄글을 물성값 대신 사용하지 않는다.
숫자는 자릿수 비교가 가능하게 정렬하고 단위 열/축을 일관되게 둔다. 긴 이름은 줄바꿈이나 즉시 전체 이름 확인 수단을 제공한다.
시험 종류·온도·변형률 속도·방향·시편 등은 해당 데이터에 실제 존재하고 판단에 필요한 항목으로 표시한다.

원본·처리 결과·모델·카드, 소재와의 연결·실제 계산 입력을 구분한다. 적용 범위·변환·근사·미지원 정보는 관련 값이나 출력 동작 옆에서 확인할 수 있게 한다.
소재 리비전은 필요한 곳에 표시하고 일반 데이터에는 리비전 편집 절차를 만들지 않는다. 연결과 저장본 확인은 프로그램이 정확한 ID로 수행하며 이름으로 관계를 추정하지 않는다.
일반 상세 화면에는 UUID·해시·스키마 주소·API 응답 전문을 나열하지 않는다. 접이식 ‘상세 근거’도 이 정보를 모아 두는 장소로 만들지 않는다.
사용자에게 필요한 근거는 사용한 실험, 처리 방법과 실제 설정, 단위 변환, 적용 범위, 근사·미지원 사항이다. 항목·값·연결 동작으로 보여준다.
소재 코드·소재 리비전과 솔버 내 소재 번호는 업무에 쓰는 정보이므로 표시한다. 실제 솔버 파일은 내용 그대로 미리보기·다운로드한다.
개발 지원에 식별자가 필요하면 별도 지원 절차에서 다룬다. 진단 화면이나 복사 버튼을 모든 자료에 선제 추가하지 않는다.

## 기본 설정·고급 설정·상태

학부 공학 지식으로 기본 업무를 완료할 수 있도록 검증된 기본값과 짧은 단계 안내를 제공한다.
전문 파라미터는 고급 설정으로 열되, 현재 결과를 해석하는 데 필요한 단위·조건·차단 사유는 숨기지 않는다.
검증되지 않은 자동 처리나 production 기본값을 임의로 확정하지 않는다.

선택·계산 중·미저장·저장 완료·이전 입력의 결과·실패·미지원 상태를 구별한다. 입력 변경 후 이전 결과가 현재 결과로 저장·출력되지 않게 한다.
이미 저장된 결과의 조회는 계속 허용한다. 실패가 원본이나 복구 가능한 편집을 지우지 않게 한다.
목록·트리는 이름과 구분에 필요한 값만 표시한다. 코드·분류·상태 설명·리비전을 제목 위아래에 반복하지 않는다. 단순 건수는 목록 합계로 모으고, 이름 없는 중간 트리 단계와 화면 소개 문구는 넣지 않는다. 소재의 코드·리비전은 소재 정보에서 확인한다.
긴 도움말을 읽어야 행동할 수 있게 하지 않는다. 보조 문구는 오해 방지, 차단 이유, 복구 방법, 공학적 해석에 필요한 경우에만 짧게 둔다.
이름 뒤에 소재·상태·조건·버전 등을 `·`나 `•`로 이어 붙이지 않는다. 비교할 속성은 열로, 상세 속성은 항목·값으로 나누고 서로 다른 자료는 구역을 나눈다. 단위계·수학 표기와 저장된 원래 이름은 임의로 바꾸지 않는다.

## 시각 체계

현재 대표 화면의 흰 데이터 면, 차분한 회색 구분, 파란 선택·주요 행동을 출발점으로 한다. 정확한 값은 공통 token에서 조정한다.
제목·section·label·수치·단위의 위계를 일관되게 유지하고 숫자는 tabular 표기를 사용한다. 상태는 색과 텍스트/표식을 함께 사용한다.
카드는 독립 소재를 비교할 때, 표는 많은 실험의 조건을 비교할 때 사용할 수 있다. 정렬·간격·선·배경은 정보를 묶는 역할을 해야 한다.
장식용 지표·빈 카드·반복 배지·긴 소개문을 추가하지 않는다. 특정 회사의 색·모서리·component를 전 화면에 강제하지 않는다.

범용 control은 접근성 기반을 활용하고 label·오류 연결·visible focus·키보드 조작을 보장한다.
성공/경고/오류색은 실제 상태에만 사용한다. 기본 대비는 WCAG AA 수준으로 확인한다.

## 표·곡선과 화면 크기

shell은 전체 화면을 사용하되 목록·그래프·native 파일 미리보기에 비교 가능한 공간을 배정한다. 탐색·form·문장은 읽기 좋은 폭을 유지한다.
넓은 화면이라고 모든 행과 글을 비례 확대하지 않는다. 데이터가 많으면 서버 검색·페이지·필요한 가상화를 사용하고 목록과 상세의 상태를 함께 검증한다.

그래프에는 물리량·단위·곡선 식별을 표시한다. 축·범례·곡선이 겹치지 않게 하고 곡선 수와 범위에 맞춰 공간을 사용한다.
전체 변형률과 소성 변형률, 공칭과 진응력, 개별 곡선·평균·산포를 정확하게 구별한다. 평균/band의 정의와 실제 계산 입력은 확인할 수 있어야 한다.

검토는 정보 위계, 공학 작업 흐름, 넓고 좁은 화면 구성의 세 축으로 수행한다. 캡처 크기와 대상 상태는 시각 매트릭스 한 곳에서 정한다.
브라우저 geometry 검사와 실제 Windows 배율·모니터의 가독성 검증을 구분한다. 지원 크기·데이터 규모별 속도 목표는 실제 연결 후 측정해 제안한다.

## 기존 명세와의 관계

기존 화면별 user flow·component 명세와 캡처는 현재 구현 및 보존할 업무를 확인하는 자료다. 과거 화면 순서·픽셀·primitive가 새 기반의 고정 의무가 되지는 않는다.
충돌하면 현재 사용자 지시와 ADR의 대체 범위를 적용하고 영향을 받은 계약을 함께 정리한다. 단위·권한·저장·복구의 중요한 계약을 단순한 시각 개선으로 삭제하지 않는다.
