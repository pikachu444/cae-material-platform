### frontend-ui-engineering 본문 초안

> 해당 화면 업무와 계약을 읽는다. 범용 primitive는 검토한 외부 기반으로 조합하고 제품 의미를 domain component에 둔다. 폼·탐색·서버 데이터의 소유자를 구분한다. 키보드와 초점, label·오류 연결, 미저장 편집과 이전 결과 처리를 확인한다. 변경한 책임에 필요한 검사만 실행한다. 시각 기준은 UI principles와 현재 승인 reference에서 읽으며 이 skill에 복제하지 않는다.

### desktop-engineering-ui 본문 초안

> 현재 선택된 목표와 대상 화면·상태를 확인한다. 미선택 시안에는 검토 상태를 표시한다. 실제 앱의 전후 화면을 정해진 viewport에서 캡처하고 원본과 필요한 영역 crop을 연다. 정보 위계, 공학 업무, 넓고 좁은 화면 배치를 각각 판단한다. 긴 이름·다량 목록·빈 결과·오류·미지원·입력 변경을 확인한다. geometry 검사와 실제 장비 가독성, 테스트 통과와 사용자 선택을 구분한다. viewport 범위와 기록 형식은 visual matrix 한 곳에서 관리한다.

### webapp-testing 본문 초안

> 기존 앱의 실행 방법과 설치된 Playwright 환경을 확인한다. 필요한 소스와 계약을 읽어 안정적인 사용자 경로를 선택한다. 화면 요소·응답 등 해당 업무의 준비 상태를 기다리고, 네트워크가 계속 연결되는 앱에서 networkidle을 공통 조건으로 쓰지 않는다. 하나의 현실적인 연결 업무와 영향을 받는 오류·복구를 검사한다. console 오류, 실제 다운로드 bytes, 저장 후 재조회, 포커스와 목록 복귀를 확인한다. 실패 시 환경·앱·테스트 원인을 구분하고 정확한 재현 절차를 남긴다.

## 개인 orchestration 대체 본문 초안

> 이 저장소와 연결된 worktree에서만 사용한다. 현재 사용자 지시, 작업 위치, 변경 범위와 완료 조건을 확인한다. 사용자가 선택한 Main 모델을 유지한다. 모델·effort를 이유 없이 자동 교체하지 않는다.
>
> Main은 요구 해석, 설계, 구현, 전체 검증, 최종 설명을 책임진다. 작은 수정은 Main이 끝낸다. 주요 UI·데이터 계약·이관처럼 독립 검토가 도움이 되는 완료 작업은 read-only reviewer 한 명에게 범위와 증거를 전달한다. 분리 가능한 구현을 사용자 또는 작업 규칙이 허용한 경우에만 맡기고, 동시에 같은 파일을 쓰지 않게 한다. 특정 모델 순서를 제품 품질의 근거로 삼지 않는다.
>
> 새 피드백은 전체 목표의 변경점으로 반영한다. 진행 기록에는 목표, 최신 결정, 실제 파일·검증 결과, 미해결 항목과 다음 행동만 남긴다. 압축 후에는 기록을 실제 상태와 대조한다. 주기적인 독백, 자동 task 증식, 불필요한 전체 history 전달을 요구하지 않는다.
>
> 실패하면 Main이 원인을 분류하고 수정 범위를 바꾼다. 독립 검수 결과는 판단 근거이며 사용자 승인이나 Main의 책임을 대신하지 않는다. 이미 쓴 reviewer를 관련 재검토에 재사용한다. 명시된 게시 권한과 검증 범위를 준수하며 개인 설정은 별도 사용자 범위에서만 수정한다.

현재 Fast/Balanced/Full 이름을 계속 쓸 필요는 없다. 유지한다면 설명용 이름으로만 두고 필수 모델/agent 수와 결합하지 않는다.
이번 작업에서 사용한 Balanced는 Main 직접 제작 후 독립 검수라는 의미이며, 향후 항상 subagent를 쓰겠다는 결정이 아니다.

## 프로필과 hook의 구체 변경 범위

- 기본 `config.toml`의 현재 Astra 선택을 유지한다. multi_agent 활성화는 사용 가능 여부이며 매 작업에 병렬 수행하라는 지시가 아니다.
- `cae-fast`, `cae-balanced`, `cae-full` 프로필에 기록된 Sol 설정은 사용자가 실제 이 launcher를 쓰는지 확인한 뒤 정리한다. 기본 권장은 모델을 route 이름에 묶지 않고 현재 사용자가 선택한 모델을 그대로 쓰는 것이다.
- `cae-full`의 medium과 skill의 xhigh 불일치는 한 곳을 임의로 고치기보다 이 강제 결합 자체를 없애서 해소한다. Astra에 특정 effort가 항상 최적이라는 근거 없는 규칙을 만들지 않는다.
- `max_concurrent_threads_per_session`은 상한일 뿐 목표 agent 수가 아니다. 이를 변경할 필요는 현재 발견되지 않았다.
- 다른 프로젝트의 trust 설정·hook hash는 그대로 보존한다. 프로젝트 `.codex/config.toml`이 없다는 사실만으로 새 파일을 만들지 않는다.
- project PreToolUse와 Git pre-push의 중복 가능성은 존재하지만 실제 이벤트 로그를 확인하기 전에는 고장/중복 실행으로 확정하지 않는다. 승인 후 안전한 실패 명령과 성공 명령으로 경로·exit code·시간을 확인한다. 실제 push 없이 수행할 수 있는 검사부터 한다.

적용 검증: 새 태스크에서 읽힌 지침과 선택 모델을 확인하고, 작은 UI 수정 하나의 실제 산출물·검증·독립 검수 필요성을 검토한다.
필요 없는 agent/질문/문서 수정이 생기지 않는지와 단위·권한·사용자 요구 검사가 유지되는지를 함께 확인한다.
