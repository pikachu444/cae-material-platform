# 프론트엔드 지침 대체 문구 초안

적용 전. 공유 내용을 복사해 두 앱에 중복 유지하지 않는다. 이행 기간에는 루트의 공통 frontend 문서를 한 곳에 두고,
`apps/web/AGENTS.md`는 legacy 차이만, `apps/web-next/AGENTS.md`는 새 기반의 실행 명령·진입 파일만 링크한다.

---

## 공통 frontend 지침

1. 해당 작업 단위와 화면/데이터 계약을 읽는다. 사용자 업무는 실험 조회, 기존 카드 조회·다운로드가 우선이다. 소재 탐색과 독립 데이터 진입은 함께 제공한다.
2. 기능 소유권은 화면 업무별로 둔다. shared에는 여러 기능에서 실제 쓰는 UI primitive와 검증된 공학 로직만 둔다. 한 번 쓰는 코드 때문에 helper/controller 계층을 추가하지 않는다.
3. 범용 Button/Dialog/Select/Tooltip 등의 접근성 동작은 검토한 외부 기반을 사용한다. 단위 입력, 조건 표, 곡선 비교, 모델 상태, 출력 지원 설명은 제품 component가 책임진다.
4. 서버 객체는 query 계층, 검색/필터/페이지/상세는 URL, 미저장 입력은 업무 form/draft, 열림·hover는 지역 UI state가 소유한다. 같은 데이터를 여러 전역 store에 복사하지 않는다.
5. API 응답을 표시 모델로 바꾸는 코드는 해당 기능의 adapter에 둔다. query key에 ID와 조회 조건을 포함하고 오래된 요청 결과가 새 선택을 덮지 못하게 한다. backend 계약의 미지원 기능은 화면만으로 있다고 꾸미지 않는다.
6. 저장 상태와 결과 유효성을 나눈다. 입력을 바꾼 뒤 이전 결과는 이전 입력과 함께 표시하고 현재 결과 저장·출력은 막는다. 저장하지 않은 편집은 화면 이동에서 조용히 사라지지 않게 한다.
7. 목록·미리보기·상세 복귀는 검색조건·페이지·선택·위치·초점을 일관되게 다룬다. 화면을 줄인다고 목록 아래에 상세를 임의로 쌓지 않는다. 좁은 화면의 전환은 명시한다.
8. 숫자와 단위·조건은 항목별로 읽게 한다. 제목에 모든 조건을 넣거나 줄글을 물성 표 대신 사용하지 않는다. 긴 이름·빈 결과·오류·미지원 출력도 정상 화면과 함께 본다.
9. 색·크기·행·간격·패널 폭은 공통 token, component CSS는 module 범위로 관리한다. 앱별 reset/token을 제외한 global 선택자를 추가하지 않는다. 경로별 4K 패치나 전체 확대 변환을 사용하지 않는다.
10. 단위·계산·검증·출력 조합을 수정할 때 검증된 입력과 허용오차로 검사한다. Storybook은 재사용 primitive/domain component의 상태 확인에, Playwright는 연결된 주요 업무에 사용한다. 두 도구에 같은 업무 검사를 중복 작성하지 않는다.
11. 첫 shell·reader는 다섯 viewport에서 검증하고 이후 작은 수정은 영향받는 화면·상태를 검사한다. 주요 layout/token 변경은 관련 전체 viewport로 넓힌다. 원본 화면 검토와 실제 장비 가독성 검증을 구분한다.
12. 완료 보고에는 사용자 결과, 검증, 한계, 남은 결정을 적는다. selector 검사 통과를 시각적 완성이나 공학적 검증으로 표현하지 않는다.

## legacy 앱에만 추가할 문구

기존 hotspot에서 책임을 옮길 때 호출자·단위/계산 로직·상태·복구 동작을 확인하고 연결된 검사와 함께 이동한다.
순수 로직 분리는 필요할 때 수행한다. 모든 이동에 동일한 function → controller → UI 순서를 요구하지 않는다.
기존 frontend guard의 예외를 새 앱에 복사하지 않는다. 삭제는 사용처와 대체 업무가 검증된 뒤 수행한다.

## 새 기반에만 추가할 문구

`apps/web-next`는 전환 전의 일시적인 경계다. 승인한 기술 기반에서 대표 조회·다운로드 업무를 먼저 연결하고
검증한 뒤 등록·처리·모델·솔버 기능을 확장한다. 새 앱의 검사 명령과 테스트 위치는 package.json 및 해당 README에 둔다.
실제 API 대신 합성 gateway를 쓰는 상태는 명확히 표시한다. 합성 시안 검사가 통과했다고 운영 준비 완료로 기록하지 않는다.

---

이 문구는 특정 화면 스타일이나 카드/표의 최종 선택을 확정하지 않는다. 화면 방향은 사용자 선택 후 UI principles와
해당 목표 reference에 한 번만 기록한다. 일반적인 시각 개선을 할 때 과거 6개 시안 전체를 다시 제작하는 의무는 제거한다.
