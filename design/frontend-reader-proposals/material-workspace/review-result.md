# 이번 작업 결과 — 화면과 규칙 변경안

2026-09-07 · RD-01의 대표 화면/규칙 변경안 제출 단계. **최종 화면 선택과 제품 전환은 아직 하지 않았다.**

추천은 **소재를 중심으로 관련 자료를 모아 보되, 실험과 솔버 카드도 바로 조회할 수 있는 작업공간**이다.
소재는 물성 카드/표, 실험은 조건별 표, 선택은 오른쪽 미리보기, 확대는 목록을 숨기는 방식으로 만들었다.
업무가 달라지면 화면도 달라진다. 처리·통계는 입력과 큰 그래프를 중심으로 따로 구성했다.

## 이번에 완성한 범위

| 업무 | 확인한 동작 | 아직 실제 제품 구현이 필요한 부분 |
| --- | --- | --- |
| 소재 탐색 | 실제 펼침 트리, 소재/시편, 별도 필터, 카드/표 전환, 항목·값·단위, 긴 이름 | 서버 검색·전체 관계·조건별 물성·소재 편집 |
| 실험 조회 | 직접 진입, 온도/속도/방향/시편 열, 곡선 우선 미리보기, 확대 상세와 복귀 | raw bytes/실제 곡선 API, 권한·지연·취소·실제 데이터 규모 |
| 기존 카드 활용 | 직접 조회, native 예시 미리보기/동일 bytes 다운로드, 파일 없음 차단 | 실제 저장 카드·IR/입력 연결·solver 지원 범위 |
| 처리 데이터 조회 | 저장된 예시의 입력 실험 링크, 재계산 없는 별도 CSV 다운로드 | 실제 저장 객체·권한·backend read-back |
| 등록 | raw/지정 양식 선택과 이후 확인 단계 안내 | 파싱·지원 형식 확인·단위/채널 mapping·소재/시편 연결·전송 |
| 처리·반복 통계 | 합성 계산, 공통 구간, 개별/평균/band, 저장 상태, 입력 변경 차단, CSV | 기존 처리 로직 통합·공학 기준·영구 저장·미저장 편집 복구 |
| 규칙 정리 | AGENTS·architecture·ADR·T/Q·skill·orchestration의 적용 문구 초안 | 승인한 범위의 활성 문서·개인 설정 변경과 실제 hook 확인 |

이번 시안에는 진짜 API를 연결하지 않았다. 그 결과를 감추는 mock 성공 메시지는 만들지 않았다.
소재만 리비전 관리하는 결정을 유지하고, 비소재 이력 생성이나 범용 출처 그래프는 추가하지 않았다.

## 화면 검토

- 정보 위계: 물성값·단위는 정렬했고 실험 조건은 열로 분리했다. 카드의 긴 제목 때문에 같은 행의 물성 위치가 어긋나지 않게 했다.
- 공학 업무: 실험 미리보기는 곡선을 먼저 보여준다. 목록의 현재 선택과 상세 대상이 일치한다. 같은 소재의 카드와 실제 계산 입력 관계를 구분했다.
- 화면 크기: 다섯 desktop viewport에서 목록 오른쪽 미리보기와 확대/복귀를 검사했다. 1366/1440에서는 넓은 표의 일부 열을 가로 스크롤하거나 미리보기를 접어서 본다. 좁은 화면에서 데이터 표를 억지로 압축하지 않는다.
- 남은 사용성 평가: 이 카드 밀도와 글자 크기를 사용자가 선택해야 한다. 4K CSS 화면의 검증은 실제 모니터·Windows 배율 가독성 승인이 아니다. 키보드 선택은 확인했지만 screen reader 실사용 검증은 아직 없다.

기존 시안과 이번 화면은 같은 화면의 색만 바꾼 변형이 아니다. 소재별 정렬된 물성 카드와 소재/시편 트리, 직접 데이터 경로,
별도의 처리 그래프 업무를 새 파일에서 구성했다. 이전 6개 비교안 파일은 보존했다. 옛 화면은 전후 비교 자료이며 새 디자인의 고정 기준이 아니다.

## 검증 기록

검사: `node design/frontend-reader-proposals/material-workspace/verify.mjs`.
원본·crop·source hash·검증 결과: `.artifacts/material-workspace-review/verification.json` 및 같은 폴더 PNG.

확인한 것은 선택/접기 분리, URL 재조회, 페이지·스크롤·초점 복귀, 카드/표 전환, Enter/더블클릭,
트리 키보드, 조건 교집합, 빈 결과와 오류 재시도, 두 종류 다운로드, 공통 구간·수치 단위 fixture,
브라우저 탭 저장/재조회, 입력 변경·혼합 조건·잘못된 설정 차단이다. 브라우저 page error는 0건이다.
수치 fixture 검사는 생산 공학 검증이 아니다. Node 24.18.0을 사용했으며 저장소 지정 24.19.0의 전체 빌드를 검증한 결과가 아니다.

문서 및 독립 검수의 최종 결과는 이 문서 하단에 기록했다. 이전 시안의 테스트 수나 검수 결과를 이번 작업의 증거로 재사용하지 않았다.

## 처음 요청한 전체 계획과의 대조

| 처음 요청한 결과 | 현재 위치 | 남은 단계 |
| --- | --- | --- |
| 실제 frontend 진단 | 기존 program/조사 + 이번 문서·규칙 충돌 확인 | 실제 API reader에서 업무 시간·응답성 측정 |
| 보존/교체·업무 대응 | program의 자산·RD 범위 + 위 업무 표 | 저장/이관 전 계약별 구현 대조 |
| UX/IA·시각 방향 | 과거 비교 이력 + 이번 소재 중심 대표 화면 | 사용자 화면 선택 |
| 전략·architecture | ADR-0037 기반 유지, 이번 책임·상태·검사 초안 | 실제 API에 연결한 작은 수직 업무 검증 |
| governance | 구체 대체 문구 준비 | 승인 범위 적용·충돌 검사·실제 작업 확인 |
| 단계 구현/전환 | RD-02/03 조회 → RD-04/05 등록·처리·확장 → RD-06/07 전환·삭제 유지 | 실제 이관 rehearsal와 일괄 전환 |
| acceptance/제품 결정 | 시안 조작과 오류는 검증, 공학·규모·장비는 별도 경계 | 기준 데이터/오차·대상 화면과 규모 합의 후 측정 |

따라서 **처음의 전체 개편이 완료된 상태는 아니다.** 이번에 승인 판단을 할 수 있는 화면과 정리 문구가 준비된 것이다.
실제 reader를 연결해 검증하기 전에 거대한 공통 framework부터 만들지 않는다. 전환 실패 시 이전 앱/배포 경로로 돌리고
데이터는 보존한다. 구형 코드·CSS·dependency는 대응 업무 검증, 소비자 0개, 이관·복구 확인 후 삭제한다.

## 사용자 판단이 남은 것

1. 지금은 이 대표 화면의 소재 카드/표와 오른쪽 미리보기 구성을 실제 구현의 기준으로 삼을지 결정하면 된다. 카드·표 둘 중 하나를 버릴 필요는 없다.
2. 규칙 변경안의 짧은 AGENTS·선택적 skill·Main 중심 작업 방식을 적용할지 결정한다. 개인 설정 변경 범위는 프로젝트 문서 정리와 나누어 확인한다.
3. 처리 구현 차례에는 최초 검증 시험과 기준 데이터·통계 의미·허용오차를 정한다. 지금 임의의 production 기본값을 승인할 필요는 없다.

소재만 리비전 관리, 데이터 직접 진입, 공학 서비스라는 제품 방향은 다시 질문하지 않는다.

## 최종 확인 — 2026-09-07

- 브라우저 검사: 최신 소스의 6개 흐름 그룹 통과. 다섯 화면 크기의 원본과 주요 영역 crop을 확인했다. 확대 상세에서는 조건 열의 폭을 제한하고 그래프에 여유 공간을 배정했다.
- 문서 검사: `cmp-check-user-guide`, `cmp-check-doc-impact --mode worktree`, `git diff --check` 통과. 문서 영향 검사의 222개 변경 파일은 기존 브랜치 변경을 포함한다. 이 시안은 reference 자료로 분류되어 해당 검사의 production visual source는 0개이며, 화면 검증은 별도 브라우저 검사와 원본 검토로 수행했다.
- 독립 검수: Main과 별도의 읽기 전용 검수자가 조작 검사, 소스 해시, 화면, 처리 제안과 규칙 초안을 확인했다. 마지막 상세 폭 보정과 표 crop도 추가 검수했고, 사용자 선택용 자료로 제출 가능하다는 판정을 받았다.
- 제출 범위: 이번 작업은 별도 redesign worktree에 있다. 원래 작업 폴더와 이전 비교 시안을 보존했다. 이번 규칙 초안은 활성 지침·개인 설정에 적용하지 않았으며 이번 변경의 commit·push·제품 전환도 진행하지 않았다.

이 판정은 시안 선택을 위한 제출 준비가 끝났다는 뜻이다. 실제 API·영구 저장·공학 결과·실제 데이터 규모·물리 4K 가독성은 위의 남은 단계에서 검증한다.
